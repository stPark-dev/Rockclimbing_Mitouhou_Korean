# 결정 기록

## D1. 그림 글자 범위 (2026-10-21, 사용자 결정)

- 질문: 그림으로 된 글자를 어디까지 한글화할까.
- 근거 기준: `docs/survey.md` §2 (그림 글자는 목록만 작성, 위치 미조사).
- 선택지: 일본어 그림만 / 영어 버튼 포함 전부 / 런타임 글자 먼저.
- **결정: 일본어 그림만.** 타이틀 로고(ロッククライミング 未踏峰への挑戦), 데이터베이스 분류 라벨 등 일본어 그림 글자는 한글로 바꾸고, GAME START·CONFIG·NEW GAME·LOAD GAME·SAVE GAME 같은 영어 그림 글자는 원문 유지.
- 영향: 그림 글자 위치·형식 조사와 `0x74` 압축 형식 해독이 범위에 들어온다(그림이 그 안에 있으면).
- 재검토: 일본어 그림이 영상(STR) 안에 있는 것으로 드러나면 영상 범위를 따로 결정한다.

## D2. 이름 입력 (2026-10-21, 사용자 결정)

- 질문: 가나 표 이름 입력을 어떻게 할까.
- 선택지: 한글 입력 표로 교체 / 영문만 남김 / 나중에 결정.
- **결정: 한글 입력 표로 교체.** 가나 표를 한글 음절 표로 바꾼다. 기본 이름 クライマー도 한국어로.
- 영향: 입력 표에 넣는 음절은 글꼴 칸을 차지한다(survey §5). 표에 넣을 음절 수와 구성은 번역 음절 집합과 칸 여유를 본 뒤 다시 제시한다. 이름 저장 구조와 다른 화면(프로필 등)에서의 재표시를 조사해야 한다.

## D3. 칸을 넘치는 번역문 (2026-10-21, 사용자 결정)

- 질문: 제자리 교체(survey §4.2)에서 번역문이 원문 칸 용량을 넘을 때 어떻게 할까.
- 근거 기준: survey §5 표본 측정(40개 중 1–5개 초과, 평균 바이트 비 0.88–0.93). 문자열의 57%(텍스트 묶음 2,613개)는 참조 경로가 미해결이라 재배치할 수 없다. 재배치할 빈 공간은 미확인.
- 선택지: 번역을 줄여 맞추기 / 포인터가 확인된 문자열을 빈 공간으로 옮기기.
- **결정: 번역을 줄여 맞추는 것을 기본으로 한다.**
- 영향: 번역 파일에 문자열별 칸 용량과 남은 바이트를 보이고, 빌드는 칸 초과를 오류로 막는다. 줄이면 뜻이 크게 상하는 문자열은 표시해 두고, 그런 것이 모이면 재배치(참조 확인된 코드 모듈 문자열만)를 따로 검토해 다시 제시한다.
- 재검토: 1바이트 음절 배정 후 실제 초과율이 표본보다 크게 나오거나, 줄인 번역이 의미를 잃는 사례가 쌓이면.

## D4. 번역 표기 원칙 (2026-10-21, 사용자 결정)

- 근거 기준: `text/glossary.json` 초안(170여 항목), survey §4.3 용어 빈도.
- **등반 용어: 외래어 음역.** 홀드·트래버스·침니·오버행·크랙·레이백 등 국내 등반계 표기. 원문이 괄호로 풀이한 곳은 풀이도 옮긴다.
- **산 별칭·루트·스테이지 이름: 뜻 번역.** 예: アルプスの孤老 → 알프스의 고독한 노인, 老人のこぶ → 노인의 혹. 실명 병기는 하지 않는다.
- **문장 부호: 。→ . 、→ ,** 마침표·쉼표 글리프를 새로 넣는다.
- **あぶみ: 형태별 명칭(사용자 제시).** 웨빙으로 만든 전통 사다리형은 에트리에(Etrier), 디딤판을 댄 사다리형은 에이드 래더(Aid Ladder). 이 게임의 장비는 1997년작 기준 에트리에로 잠정하고, 데이터베이스 「登山道具」 그림으로 형태를 확인해 확정한다.
- 영향: 용어집 `_rules`를 이 결정으로 고정한다. 개별 이름의 번역어는 여전히 후보(candidate)이며 번역·검토 중 사용자 확인을 거친다.

## D5. 말투·이름 처리·대량 번역 진행 (2026-10-21, 사용자 검수)

- 근거: 등반·식사 화면 초벌 83단위 표본 검수(사용자). 판정: **조건부 승인 — 같은 기준으로 대량 번역 진행.**
- **말투(화자 단위로 통일):**

  | 상황 | 말투 |
  |---|---|
  | 클라이머 의지·결심 | ~하자! / ~하겠어! |
  | 클라이머 감탄·안도 | ~겠네. / ~같아. |
  | 클라이머 위험 경고 | ~다! / ~야! |
  | 클라이머 실수·부상 | ~말았어. / ~버렸군. |
  | 전문가의 경고·설명 | ~입니다. / ~하십시오. |
  | 시스템의 사건 서술 | ~했습니다. / ~합니다. |

  같은 클라이머라면 ~군·~네·~어를 섞어도 된다. 원문에서 화자 구분이 확인되면 인물별 규칙이 우선한다.
- **이름 자리(`{F8:00}`, 정체 미확인):** 받침에 따라 바뀌는 조사를 붙이지 않는다. 「{이름} 쪽으로/쪽을」, 「{이름}에게」, 「{이름}, …」 문형을 쓰고, 「{이름}의 몸이」는 반복을 피한다. 정체 확인 전까지 코드의 원래 바이트를 그대로 유지한다.
- **질문과 선택지가 합쳐진 문자열**은 독립 UI 단위인지 화면에서 확인한다(예: 今の御気分は… + 선택지 3개).
- **용어:** ロッククライミング → 락클라이밍(타이틀과 통일), アタックする → 도전하다(등반 상황에서 공략하다 허용), ネンザ → 대사는 삐다·상태명은 염좌, 小休止 → 짧은 휴식, ハーケン → 하켄(피톤과 혼용하지 않음), 人工 → (인공) 괄호 유지.
- **남은 확인(분량 확장과 병행):** 「小休止{F9:01}」류 F9 연결 6건, 칸 초과로 줄인 문장의 화면 검증, `{F8:00}` 정체, 바이트 판정 수정 후 원본–추출 대응 검사(코퍼스 테스트가 원문 바이트 일치를 검사함).

## D6. 숫자 뒤 조사와 雪渓 (2026-10-21, 사용자 결정)

- **런타임 숫자 뒤 조사:** `{FA:xx}`로 들어가는 숫자 뒤에 받침 의존 조사를 붙이지 않는다. 「ステージ{n}への移動」→ **「{n}번 스테이지로 이동」**. 글자 수가 모자라면 「{n}스테이지로 이동」 허용. 숫자 코드 위치를 옮겨도 정상 출력되는지 화면에서 확인하고, 안 되면 「스테이지{n} 이동」처럼 조사를 생략한다.
- 정정 기록: 초벌 보고에서 1·7·8에 「으로」가 맞다고 잘못 적었다. 숫자 읽기 끝소리 기준으로 1·2·4·5·7·8·9는 「로」(ㄹ 받침 예외 포함), 3·6·10은 「으로」.
- **雪渓 → 설계(雪溪) 승인.** 지형명·기술 설명·상태 표시는 「설계」, 클라이머 대사는 「눈 덮인 골짜기」 허용. 「눈골짜기」 「만년설 지대」는 쓰지 않는다.
